# EduShelf — электрондық білім беру ресурстары

Қазақ тіліндегі ASP.NET Core MVC кітапханасы. Студент материалдарды іздейді, PDF қарайды, жүктейді және таңдаулыға сақтайды. Оқытушы материал қосады, өңдейді, жариялайды және архивтейді. Әкімші материалдарды, рөлдерді және анықтамалықтарды басқарады.

Екінші кезең PDF мәтінін алуды, OpenAI талдауын, SQL кезегіндегі фондық өңдеуді, толық мәтін бойынша іздеуді, ұқсас материалдарды және рөлмен шектелген аналитиканы қосады. API кілті болмаған жағдайда кітапхана жұмыс істейді, AI бөлімі «AI қызметі бапталмаған» күйін көрсетеді. Нақты тексерулер [PHASE-2-STATUS.md](PHASE-2-STATUS.md), код түсіндірмесі [STUDY.md](STUDY.md), қорғау сценарийі [DEFENSE.md](DEFENSE.md) ішінде. [Бірінші кезең есебі](PHASE-1-STATUS.md) тарихи тексеру нәтижелерін сақтайды.

## Технологиялар және орта

| Бөлік | Нұсқа / шешім |
| --- | --- |
| Платформа | .NET 10 LTS, `net10.0` |
| Осы ортада анықталған SDK | `10.0.401` |
| Осы ортада анықталған runtime | `10.0.12` |
| MVC және беттер | ASP.NET Core MVC, Razor, HTML/CSS/JavaScript |
| Деректер және аккаунттар | EF Core SQL Server және ASP.NET Core Identity `10.0.13` |
| EF CLI | Жобаға бекітілген `dotnet-ef 10.0.13` |
| Деректер базасы | Microsoft SQL Server; басқа provider қолданылмайды |

2026 жылғы 20 қазанда тексерілген [Microsoft қолдау саясаты](https://dotnet.microsoft.com/en-us/platform/support/policy) бойынша .NET 10 — LTS, қолдау мерзімі 2028 жылғы 14 қарашаға дейін. Ресми ағымдағы patch — `10.0.13`. Осы компьютердегі `10.0.12` runtime нұсқасын жариялау алдында қолдаудағы соңғы patch нұсқасына жаңартыңыз.

Осы ортада **`MSSQLSERVER` default instance**, SQL Server нұсқасы **`16.00.1000`**, қосылу мекенжайы **`.`** тексерілді. `SQLEXPRESS` бар деп болжанбайды: төмендегі нұсқа тек сол instance бөлек орнатылған ортаға арналған.

SSMS 21 — базаны басқару клиенті. Оның орнатылуы SQL Server қозғалтқышының орнатылғанын немесе іске қосылғанын білдірмейді.

## Жылдам іске қосу

PowerShell терезесін жоба каталогында ашыңыз:

```powershell
dotnet --info
dotnet restore
dotnet tool restore
dotnet build --no-restore
```

Содан кейін төменде берілген **миграция** немесе **SSMS SQL скрипті** жолының бірін таңдаңыз. Демо деректер қажет болса, бөлек seed орындаңыз. Қосымшаны іске қосу:

```powershell
dotnet run --launch-profile http
```

Браузерде [http://localhost:5046](http://localhost:5046) ашыңыз. HTTPS профилі: `dotnet run --launch-profile https`, мекенжайы `https://localhost:7209`; жергілікті HTTPS үшін .NET development certificate бапталған болуы керек.

Қалыпты web іске қосылу базаны автоматты түрде өзгертпейді және демо аккаунт жасамайды. `--check-db`, `--migrate`, `--seed` — қызметтік әрекеттер: орындалып, процесс аяқталады.

## SQL Server қосылымы

Қосылым кілті — `ConnectionStrings:DefaultConnection`. Коммиттелген `appsettings.json` жергілікті Windows Authentication мысалын қамтиды; онда пароль жоқ. Өз ортаңызға арналған мәнді user-secrets немесе environment variable арқылы үстінен орнатыңыз.

**Жергілікті default instance:**

```powershell
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=.;Database=EduShelf;Trusted_Connection=True;Encrypt=True;TrustServerCertificate=True;Connect Timeout=5"
```

**SQLEXPRESS бөлек орнатылған болса ғана:**

```powershell
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=.\SQLEXPRESS;Database=EduShelf;Trusted_Connection=True;Encrypt=True;TrustServerCertificate=True;Connect Timeout=5"
```

Environment variable баламасы:

```powershell
$env:ConnectionStrings__DefaultConnection = 'Server=.;Database=EduShelf;Trusted_Connection=True;Encrypt=True;TrustServerCertificate=True;Connect Timeout=5'
```

Бұл айнымалы ағымдағы PowerShell процесіне және одан іске қосылған қосымшаға әсер етеді. Windows Authentication кезінде қосымшаны іске қосқан Windows пайдаланушысына SQL Server ішінде тиісті құқықтар берілуі керек. `TrustServerCertificate=True` мысалы жергілікті ортаға арналған; жарияланған ортада сенімді сервер сертификатын және `TrustServerCertificate=False` қолданыңыз.

Қосылымды тексеру:

База әлі жасалмаса, алдымен келесі бөлімдегі миграция немесе SQL скрипті арқылы схеманы дайындаңыз.

```powershell
dotnet run --launch-profile http -- --check-db
```

Қате болса: SQL Server қызметінің жұмысын, instance атауын, Windows login рұқсатын және көрсетілген базаға қолжетімділікті тексеріңіз. SSMS ішіндегі қосылым мен қосымшаның қосылым жолы бір серверге бағытталуы керек. SQL Server қолжетімсіз болса, SQLite-қа ауысу қарастырылмаған.

## Схеманы дайындау: екі баламалы жол

`Data/Migrations` және [scripts/EduShelf.sql](scripts/EduShelf.sql) бір EF схемасынан алынған. Скрипт `__EFMigrationsHistory` кестесін тексеріп, жетіспейтін миграцияларды ғана орындайды. Базаны дайындаудың бір жолын таңдаңыз; әр іске қосуда екеуін қатар орындау қажет емес. EF тәсілдері туралы [Microsoft құжаттамасы](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying).

Екінші кезеңнің `20261020110540_PhaseTwoProcessingSearch` миграциясы бірінші кезең схемасына мәтін, кезек, embedding, іздеу және бетбелгі құрылымдарын қосады. Бар аккаунттар, материалдар және PDF файлдары сақталады; базаны қайта жасаудың қажеті жоқ.

### A. EF миграциясы

```powershell
dotnet tool restore
dotnet ef database update
```

Немесе дәл сол миграцияларды қолданбаның қызметтік командасымен орындаңыз:

```powershell
dotnet run --launch-profile http -- --migrate
```

База әлі жоқ болса, оны жасауға құқығы бар Windows login қажет. Құқық жеткіліксіз болса, әкімші базаны алдын ала жасап, migration орындаушысына схема өзгерту құқығын береді.

### B. SSMS 21 және дайын idempotent SQL

1. SSMS 21 ішінен **Database Engine**, **Server name: `.`**, **Windows Authentication** таңдап қосылыңыз. Өз ортаңызда басқа instance болса, тексерілген нақты атауын қолданыңыз.
2. Object Explorer → Databases → New Database арқылы `EduShelf` базасын жасаңыз. Егер ол бар болса, сол базаны таңдаңыз.
3. [scripts/EduShelf.sql](scripts/EduShelf.sql) файлын SSMS ішінде ашыңыз. Query терезесіндегі database тізімінен **EduShelf** таңдаңыз.
4. Скрипттің алдына төмендегі екі жолды қосып, дұрыс база таңдалғанын тексеріңіз; кейін скриптті орындаңыз:

```sql
USE [EduShelf];
GO
```

Скрипттің өзі **базаны жасамайды**. Оны `master` базасында орындамаңыз. Өзге атау таңдасаңыз, `USE` және `DefaultConnection` екеуін де сол атауға сәйкестендіріңіз.

Миграция өзгергенде SQL артефактын қайта жасау:

```powershell
dotnet ef migrations script --idempotent --output scripts/EduShelf.sql
```

## Демо деректер және аккаунттар

`--seed` рөлдер мен анықтамалықтарды толтырады. Демо аккаунттар мен алты оқу PDF-ы тек **Development** ортасында және `Seed:DemoEnabled=true` болғанда қосылады. Демо құпиясөздер репозиторийде сақталмайды.

Алғашқы баптау мысалы; `<...>` мәндерін өзіңіздің мәндеріңізбен ауыстырыңыз:

```powershell
dotnet user-secrets set "Seed:DemoEnabled" "true"
dotnet user-secrets set "Seed:AdminEmail" "admin@edushelf.local"
dotnet user-secrets set "Seed:AdminPassword" "<ӘКІМШІНІҢ_ҚҰПИЯСӨЗІ>"
dotnet user-secrets set "Seed:TeacherEmail" "teacher@edushelf.local"
dotnet user-secrets set "Seed:TeacherPassword" "<ОҚЫТУШЫНЫҢ_ҚҰПИЯСӨЗІ>"
dotnet user-secrets set "Seed:StudentEmail" "student@edushelf.local"
dotnet user-secrets set "Seed:StudentPassword" "<СТУДЕНТТІҢ_ҚҰПИЯСӨЗІ>"
dotnet run --launch-profile http -- --seed
```

Үш email бір-бірінен бөлек болуы керек. Құпиясөз талабы: кемінде 8 таңба, бас және кіші латын әрпі, сан және арнайы таңба. Бар демо аккаунтқа бұрын орнатылған жеке кіру деректерін қолданыңыз. Құпия конфигурацияның барлық мәндерін терминалға немесе есепке шығармаңыз.

Seed қайта орындалса, аккаунттар мен материалдар қайталанбайды, бар материалдың редакциялық өзгерістері сақталады. Seed **бар аккаунттың құпиясөзін ауыстырмайды**. Password конфигурациясын өзгерту бұрын жасалған аккаунттың кіру деректерін өзгертпейді. Жаңа таза демо базаға seed жасағанда жаңа конфигурация қолданылады. Құпиясөзді қалпына келтіру интерфейсі қосылмаған.

Демо жинақ: сызықтық теңдеулер, үшбұрыштың ауданы, бірқалыпты қозғалыс, алгоритм, мәтіннің негізгі ойы және өсімдік жасушасы. Соңғы материал тек тіркелген пайдаланушыларға арналған; қалған бесеуі жария. Файлдар [DemoFiles](DemoFiles) ішінде, олардың генераторы [scripts/generate-demo-pdfs.py](scripts/generate-demo-pdfs.py). Web қосымшасын іске қосуға Python қажет емес. Seed жалған қаралым, жүктеу немесе AI нәтижесін қоспайды.

### Production әкімшісін бастапқы жасау

Production ортасында демо аккаунттар автоматты қосылмайды. Алғашқы әкімші үшін қорғалған орта конфигурациясына `Bootstrap:AdminEmail` және `Bootstrap:AdminPassword` орнатып, оператор ретінде **бөлек** `--seed` орындаңыз. Environment variable атаулары — `Bootstrap__AdminEmail`, `Bootstrap__AdminPassword`. Production ортасында user-secrets автоматты жүктелмейді.

Екі мән де міндетті. Бапталған email арқылы әкімші рөлі беріледі; бар аккаунттың құпиясөзі ауыспайды. Бастапқы баптаудан кейін bootstrap құпиясөзін іске қосу ортасынан алып тастаңыз. Тіркелу беті тек `Student` рөлін береді; `Teacher` пен қосымша `Admin` рөлдерін әкімші интерфейсі басқарады. Соңғы әкімшінің рөлін алып тастауға сервер рұқсат бермейді.

## Файлдар және қолжетімділік

| Параметр | Әдепкі мән |
| --- | --- |
| `Storage:RootPath` | `App_Data/uploads` |
| `Storage:MaxFileSizeMb` | `20` |
| Қолдау | PDF |

Сақтау каталогы `wwwroot` сыртында болуы керек. Қосымшаның Windows process identity-іне сол каталогқа оқу/жазу құқығын беріңіз. Сервер файл атауын GUID арқылы жасайды; бастапқы атау тек метадерек ретінде сақталады. Кеңейтім, `%PDF-` сигнатурасы және нақты көлем тексеріліп, SHA-256 hash есептеледі. Ағынмен көшіру үлкен файлды түгел жедел жадқа жүктемейді.

Файл тек авторизацияны тексеретін controller арқылы беріледі. `Draft` және `Archived` — авторға және әкімшіге; `Published + Public` — барлық оқырманға; `Published + Authenticated` — тіркелген пайдаланушыға көрінеді. Жабық материал іздеу нәтижесіне де қосылмайды. PDF preview және Range сұраулары қосымша қаралым/жүктеу жасамайды; жүктеу саны арнайы POST батырмасымен есептеледі.

Сақтық көшірмеге **SQL базасын және upload каталогын бірге** қосыңыз: тек базаны көшіру PDF файлдарын қалпына келтірмейді. `App_Data`, build нәтижелері және жергілікті құпия конфигурация `.gitignore` ішінде. `DemoFiles/*.pdf` deploy құрамына кіреді, пайдаланушы upload файлдары бөлек басқарылуы керек.

## Тексеру

```powershell
dotnet restore
dotnet build --no-restore
dotnet test Tests/EduShelf.Tests.csproj --no-restore
```

SQL Server интеграциялық тесттері үшін жеке master қосылымын орнатыңыз:

```powershell
$env:EDUSHELF_TEST_CONNECTION = 'Server=.;Database=master;Trusted_Connection=True;Encrypt=True;TrustServerCertificate=True'
dotnet test Tests/EduShelf.Tests.csproj --no-restore
```

Бұл тесттер нақты SQL Server provider мен миграцияны қолданады. Әр тест fixture бірегей атауы бар уақытша база жасап, соңында жояды; login-ге `CREATE DATABASE` және оны жою құқығы қажет. Қосымшаның `EduShelf` базасын тест базасы ретінде көрсетудің қажеті жоқ. Айнымалы берілмесе SQL тесттері **өткізіліп жіберіледі**; бұл олардың тексеруден өткені болып саналмайды.

Тесттер серверлік авторизацияны, жабық материал іздеуін, файл валидациясын, orphan файлды тазалауды, тақырыптың пәнге тиесілігін, favorites бірегейлігін, рөлдер мен соңғы әкімшіні қорғауды қамтиды. Екінші кезең PDF мәтінін, AI жауабын және ақауларын mock арқылы, SQL кезегін, іздеуді, ұсыныстарды, аналитика шектеулерін және жеке бетбелгілерді тексереді. Нақты іске қосу саны [PHASE-2-STATUS.md](PHASE-2-STATUS.md) ішінде.

## PDF мәтіні және фондық кезек

Жаңа PDF сақталғанда SQL Server-дегі `ProcessingJobs` кестесіне мәтін алу тапсырмасы қосылады. Web host ішіндегі `BackgroundService` оны бөлек DI scope ішінде орындайды. Бір материалға бір кезек жазбасы бар; қайталанатын сұрау қатар екінші тапсырма жасамайды. Аяқталмаған жұмыс lease уақыты өткеннен кейін қайта алынады. Қайталау саны мен өңдеу уақыты шектелген.

PdfPig кітапханасы мәтінді Unicode күйінде беттер бойынша алады. PDF талдауы бөлек `dotnet` процесінде орындалады: timeout біткенде сол процесс тоқтатылады. Мәтін `ResourceTextPages` ішінде, іздеуге арналған біріктірілген мәтін SQL ішінде сақталады. Бүлінген, шифрланған немесе мәтінсіз скан PDF түсінікті күй береді; бастапқы материал мен файл сақталады. OCR қосылмаған. Қамтылу шегіне жеткен құжаттың толық өңделмегені материал бетінде көрсетіледі.

| Конфигурация | Әдепкі мән |
| --- | --- |
| `Extraction:MaxPages` | `100` |
| `Extraction:MaxCharacters` | `200000` |
| `Extraction:TimeoutSeconds` | `30` |
| `Worker:Enabled` | `true` |
| `Worker:PollSeconds` | `3` |
| `Worker:LeaseSeconds` | `240` |
| `Worker:MaxAttempts` | `3` |
| `Worker:ProcessingTimeoutSeconds` | `180` |

Бұрыннан бар материалдардың мәтінін алғаш рет индекстеу және кезекті web host қоспай орындау:

```powershell
dotnet run --launch-profile http -- --index-existing
dotnet run --launch-profile http -- --process-pending
```

Қалыпты іске қосылған сайтта worker кезекті автоматты орындайды. `--process-pending` бір шақыруда ең көбі 1000 job орындайды; кезек үлкен болса команданы қайталауға болады. `--index-existing` файлдарды немесе аккаунттарды жоймайды. PDF ауысқанда мәтін, AI қорытындысы, embedding және жеке бетбелгі файл hash-ымен салыстырылады; ескі файл деректері жаңа файлдың нәтижесі ретінде көрсетілмейді.

## OpenAI талдауы және embeddings

Қолданыстағы интеграция OpenAI Responses API арқылы structured JSON қорытындысын, embeddings API арқылы вектор алады. Материал бетінде Teacher өз материалын, Admin кез келген материалды талдауға жібереді. HTTP сұрауы тапсырманы ғана кезекке қояды. Статус endpoint-і де осы иелік ережесін тексереді. Күй polling арқылы жаңарады; polling қаралым немесе жүктеу оқиғасын жазбайды.

API кілтін **Development** үшін user-secrets ішінде орнатыңыз:

```powershell
dotnet user-secrets set "Ai:ApiKey" "YOUR_API_KEY"
dotnet user-secrets set "Ai:Provider" "OpenAI"
dotnet user-secrets set "Ai:Endpoint" "https://api.openai.com/v1/"
dotnet user-secrets set "Ai:Model" "gpt-4.1-mini"
dotnet user-secrets set "Ai:EmbeddingModel" "text-embedding-3-small"
dotnet user-secrets set "Ai:EmbeddingDimensions" "1536"
```

Environment variable баламасы: `Ai__ApiKey=YOUR_API_KEY`; қалған кілттерде де `:` орнына `__` қолданылады. Production ортасында қорғалған environment конфигурациясын қолданыңыз. Кілтті `appsettings.json`, README, лог немесе Git ішінде сақтамаңыз. Кілт өзгерсе, host-ты қайта іске қосыңыз. Бұл мысал нақты құпия мәнді қамтымайды.

| Конфигурация | Әдепкі мән / қызметі |
| --- | --- |
| `Ai:EnableEmbeddings` | `true`; `false` болса тақырыптық ұсыныстар қалады |
| `Ai:RequestTimeoutSeconds` | `45` |
| `Ai:MaxRetries` | `2` |
| `Ai:ChunkCharacters` | `12000` |
| `Ai:MaxChunks` | `4` |
| `Ai:MaxOutputTokens` | `1800` |

Нәтиже негізгі тақырыпты, 5–12 кілт сөзді, қазақша қысқаша мазмұнды, үш қиындық деңгейінің бірін және бар пән/тақырып ұсынысын қамтиды. Сервер JSON өрістерін және анықтамалық сәйкестігін тексереді. Құжат ішіндегі нұсқаулар сенімсіз талдау дерегі ретінде беріледі. Ұзын құжат шектелген бөліктермен өңделеді; талданған таңба саны мен ішінара қамтылу SQL-да сақталып, интерфейсте көрсетіледі. AI ұсынысы пән мен тақырыпты автоматты ауыстырмайды: автор немесе Admin жеке POST формасымен растайды.

Embedding векторлары model, dimensions және файл hash-ымен SQL-да JSON ретінде сақталады. Бір материал ашылған сайын API шақырылмайды. Ұсыныс қызметі бірдей provider, модель, өлшем және ағымдағы hash-ы бар векторларды шектелген кандидаттармен салыстырады; SQL native vector міндетті емес. `Recommendations:MaxCandidates=200`, `Recommendations:Count=4`. Embedding жоқ болса, пән/тақырып/тег бойынша нәтиже **«Тақырып бойынша ұқсас»** деп көрсетіледі. Қолжетімді сәйкес материал аз болса, үштен аз ұсыныс болуы мүмкін.

**API кілтінсіз:** Identity, каталог, PDF мәтінін алу және мәтін іздеу, preview/download, таңдаулы, тарих, басқару, аналитика, CSV экспорт, тақырыптық ұсыныстар, сілтемені көшіру және жеке PDF бетбелгісі жұмыс істейді. Нақты AI қорытындысы мен жаңа embedding алынбайды. Жалған AI нәтижелері жасалмайды.

## Full-Text Search және мәтіндік fallback

Вектордың нақты кірісі — AI анықтаған тақырып, қазақша қысқаша мазмұн және кілт сөздердің алғашқы 2000 таңбасы. Бұл толық PDF-тың әр сөйлеміне бөлек embedding жасау емес. Бұрын талдау сұралған материалдың файлы ауысса, ескі нәтижелер алынып, мәтінмен бірге AI/embedding қайта өңдеуге кезекке қойылады.

Іздеу атау, сипаттама, PDF мәтіні, тег, AI кілт сөздері және қысқаша мазмұн бойынша жүреді. Сұрау серверде рұқсатпен сүзілген SQL жиынында орындалады. Атау сәйкестігіне басымдық беріледі. Пән, тақырып, түр, тег және қиындық сүзгілері pagination кезінде сақталады. Табылған үзінді Razor арқылы қауіпсіз кодталады.

`Search:Mode=Auto` SQL Server Full-Text қолжетімділігін тексереді; `Search:AllowLikeFallback=true` толық мәтін компоненті жоқ ортада параметрленген LIKE/EF іздеуін қосады. `Search:Mode=Like` осы мәтіндік жолды тікелей таңдайды. LIKE fallback семантикалық іздеу емес. Қазақ тіліне арнайы word breaker бар деп болжанбайды; қолжетімді тілдер тексеріліп, neutral language (LCID 0) қолданылады. Full-Text сұрауы `FREETEXTTABLE` арқылы пайдаланушы сөзін параметр ретінде қабылдайды. Ортада нақты қай режим тексерілгені status есебінде жазылады.

Full-Text компоненті орнатылған instance үшін негізгі миграциядан кейін SSMS 21 ішінде `EduShelf` базасын таңдап, [scripts/setup-fulltext.sql](scripts/setup-fulltext.sql) скриптін **транзакциядан тыс** орындаңыз. Скрипт компонент пен neutral word breaker бар-жоғын тексереді, `EduShelfSearch` catalog және `ResourceSearchDocuments.SearchText` индексін бір рет жасайды. Индекстің бастапқы population-ы асинхронды жүреді. Компонент жоқ болса скрипт түсінікті хабарламамен аяқталып, негізгі схема мен fallback сақталады. Full-Text DDL негізгі EF миграциясының транзакциясына кірмейді.

## Аналитика және CSV

Sidebar → **Аналитика**, мекенжайы `/Analytics`. Teacher өз материалдарының, Admin бүкіл жүйенің нақты SQL оқиғаларын көреді. Есептер: ең көп қаралған/жүктелген материалдар, күндік қарау мен жүктеу, пәндердегі жария материалдар, студент белсенділігі және AI жіктелуі. Кестеден материалға өтуге болады. Уақыт аралығы тексеріледі; оқиғасыз күндер нөлмен көрсетіледі. Деректер UTC сақталады, күн шекарасы Asia/Qyzylorda (UTC+5) бойынша есептеледі. Аноним қаралым нақты студентке жазылмайды.

Әдепкі аралық — соңғы 30 жергілікті күн, ең ұзын аралық — 366 күн. Мысалы: `/Analytics?From=2026-10-01&To=2026-10-20`; CSV: `/Analytics/Export?From=2026-10-01&To=2026-10-20`. Күндер ISO `yyyy-MM-dd` түрінде беріледі. Күн сүзгісі оқиғаларға қолданылады; материал/пән/AI саны ағымдағы күйді көрсетеді, бұл бет пен экспортта белгіленген. Танымал материалдар — алғашқы 10, student қатары — 100, пән қатары — 200, AI тақырыптары — 20 нәтижемен шектеледі.

CSV экспортта UTF-8 BOM, ұяшық escaping және formula injection қорғанысы бар; export endpoint-і беттегі рөл шектеуін қайта қолданады. PDF preview, Range және статус polling есептерді көбейтпейді.

## Белгілі шектеулер

- Framework-dependent жариялауда `dotnet` host орнатылған болуы керек: PDF мәтінін алатын бөлек процесс сол EduShelf жинағын іске қосады. Процестің уақыт, бет, кіріс және нәтиже көлемі шектелген; оған операциялық жүйе деңгейіндегі жеке RAM квотасы қойылмаған. Күрделі бір бет parser ішінде нәтиже қиылғанға дейін жад қолдануы мүмкін.
- OCR жоқ: мәтінсіз скан іздеуге және AI талдауына оқылатын мәтін бермейді.
- PDF/AI көлем және уақыт шектері әдейі бар; қамтылмаған бөлік қорытындыға кірмейді.
- Embedding салыстыруы шектелген кандидат жиынында орындалады; үлкен өндірістік корпус үшін бөлек іздеу инфрақұрылымы керек болуы мүмкін.
- SQL Full-Text компонентінің орнатылуы SQL Server instance-іне байланысты. Fallback қосылған ортада каталог жұмысын жалғастырады.
- Нақты сыртқы API шақыруы кілт пен желі рұқсатына тәуелді. Mock тестінің өтуі live API тексеруін алмастырмайды.
- Браузердегі PDF viewer-дің `#page=` қолдауы браузерге байланысты. Бетбелгі серверде жеке сақталады, PDF беті автоматты бақыланбайды: пайдаланушы нөмірді енгізеді.
- Браузер, live API, SSMS интерфейсі және production deploy тексерулерінің нақты статусы [PHASE-2-STATUS.md](PHASE-2-STATUS.md) ішінде берілген.
